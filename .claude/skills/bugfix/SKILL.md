description: 修 bug 的固定流程：重現測試 → 根因 → 修正 → verify → 錯誤紀錄。使用者回報 bug、錯誤或異常行為時使用。
argument-hint: <bug 描述>
---

修這個 bug：$ARGUMENTS

1. **釐清**：確認預期行為與實際行為。資訊不足就先問使用者，不要猜。
2. **定位**：用 `explorer` 子代理找相關程式碼，回報可疑位置。
3. **重現**：在對應的 `__tests__/` 寫一個會失敗的測試，跑 `npx jest <路徑>` 確認它真的失敗、且失敗原因就是這個 bug。無法用單元測試重現時，說明原因並和使用者確認替代驗證方式。
4. **根因**：說明為什麼會壞（一兩句），不是只描述症狀。找不到根因前不要動手修。
5. **修正**：最小改動修根因，不順手重構。
6. **驗證**：重現測試通過，`npm run verify` 全過。不可刪除、跳過或放寬任何測試。
7. **錯誤紀錄**：在對應的 `.claude/rules/<backend|frontend|testing>.md`「錯誤紀錄」加一行 `- 根因 → 以後做法`；跨領域記在 `CLAUDE.md`。必須具體可執行。
8. **回報**：根因、改了什麼、測試名稱，各一兩句。
